# 上下文查词质量验收

Dictionary 的核心目标是解释“这里的这个词”。验收分别检查选词、来源语境、AI 释义和阅读交互，不能用一次请求成功代替这些结论。

## 本阶段的范围

1. 核心质量：主窗口、Books 与浏览器的选词和语境路径，以及上下文释义。
2. 安装分发：首次启动、模型准备、另一台 Mac 的安装体验与正式安装包。
3. 持续维护：版本发布、回退、兼容性修复及后续更新机制。

0.2.0 将解释模型对照与首次配置、分发准备合并为一次交付。保留既有原生界面，不加入与阅读查词无关的功能，也不为了修正一个词反复叠加专用提示词或词义特例。

## 验收规则

| 项目 | 通过条件 | 不足以证明通过的证据 |
| --- | --- | --- |
| 选词一致 | 提交目标与当前选区一致；后一次查询不会被旧结果覆盖 | 弹窗成功出现 |
| 语境对应 | 原句包含目标的正确出现位置；重复词、页面片段和过期来源按证据降级 | 语境里能搜到相同字母 |
| 词义与词性 | 符合这句话中的实际用法；只解释目标，备选不混入不相关含义 | 返回合法 JSON、词典中存在该词 |
| 原句翻译 | 保留原句各分句、否定、数量和名字；无已确认原句时不显示模型编造的原句 | 译文流畅，或包含一个期望关键词 |
| 未知与无效回答 | 不编造未知标签的含义；缺失、原词回显及字符串 `null` 不作为有效释义展示 | 模型返回了字符串 |
| 阅读交互 | 切词、翻页、取消、关闭、固定后状态正确；设置与权限在普通更新后保留 | 受控 Provider 单元测试通过 |

固定关键样例出现词义错误、编造未知含义或错误来源声明时，语义验收不通过。
一般修复可以独立交付，但不得因此宣布语义质量或未实测的软件兼容性已经通过。

## 可重复的本地评估

`DictionaryQualityTests` 的 `acceptance` 集合复用 16 条已有合成样例与判定标准，
涵盖收费/充电、银行/河岸、经营/流动、搭配、存在句/地点、短语、否定、未知标签与无语境查询。
这是固定回归集，不是新的盲测集，也不能估计所有英文文本上的准确率。

```sh
DICTIONARY_QUALITY_LIVE=1 \
DICTIONARY_QUALITY_SET=acceptance \
DICTIONARY_QUALITY_ROUNDS=3 \
DICTIONARY_QUALITY_ROUTE=manual \
swift test --filter DictionaryQualityTests/recordLocalQualityResponses
```

需要本机 Ollama 与已安装的本地模型。默认使用 `qwen2.5:7b`；可用
`DICTIONARY_QUALITY_MODEL` 指定其他已安装模型。评估不会下载模型、改写应用设置或使用云端回退。
轮数限于 1–3；样例集或输入方式拼写错误会中止，不会悄悄换成另一个集合。

三种 `DICTIONARY_QUALITY_ROUTE`：

- `manual`：调用生产的手动输入请求构造路径。
- `anchored`：用合成 UTF-16 选区和原句范围构造生产请求。
- `fragment`：提供推断语境，但不提供已确认原句。

这些是输入证据的模拟方式，**不代表已经操作真实 Books 或加载浏览器扩展**。
它们均调用真实 `OllamaProvider`。每条记录包含输入、原句、判定标准、实际系统提示词摘要、原始回答和耗时。
需要逐条审查主释义、词性、备选及句译；不能对整段回答做关键词匹配后自动宣布正确。
测试命令成功只表示响应记录完成。实机证据与语义判定应另外记录，含私人资料的日志不提交。

## 2026-11-07 验收结果

默认 `qwen2.5:7b`，生产提示词与生成设置未作调整：

| 输入方式 | 轮数 × 样例 | 已解码响应 | 本机响应时间中位数 |
| --- | --- | --- | --- |
| 手动输入 | 3 × 16 | 48 / 48 | 0.96 秒 |
| 合成精确选区 | 1 × 16 | 16 / 16 | 1.07 秒 |
| 合成片段语境 | 1 × 16 | 16 / 16 | 0.80 秒 |

时间只描述这次本机运行，不是其他硬件的速度保证。80 次响应全部解码成功，**语义验收未通过**：

| 关键样例 | 观察到的问题 |
| --- | --- |
| `There are two books on the desk.` 中的 `There` | 五次均未正确解释存在句作用，出现地点含义或错误词性 |
| `making mistakes` 中的 `making` | 精确选区和片段方式均出现“制作”；手动方式也有释义范围过宽的回答 |
| 合成未知标签 `zyxqvexample` | 精确选区和片段方式编造“示例”含义；手动方式三次只回显标签 |
| 无语境的未知标签 | 一次返回字符串 `"null"`，而非 JSON `null` |
| 片段方式中的 `look up` | 主释义正确，但词性仅标为普通动词 |

银行/河岸、收费/充电、经营/流动等对照在本次观察中能够区分；这些通过项不能抵消上表的失败项。
更大本地模型的一次原设置对照未完成，在约三分钟没有可审查输出后中止；没有据此更换默认模型或作质量结论。

这一轮已修复两个可确定的软件问题：

- 手动原句定位按完整目标匹配，不再把 `bankruptcy` 中的 `bank` 当作目标出现位置。
  数字、下划线、组合字符边界和重复目标均有回归用例。
- 字符串 `null` 不再作为释义、词性、句译或备选显示。原始回答仍保留供检查；
  这项显示修复不会判断或纠正“制作”“示例”等看似有效的错误含义。

### 兼容性证据范围

浏览器生产捕获脚本在真实 WebKit 引擎中运行的集成测试，以及 Books 的受控
复制确认、来源变化、页面边界和重复词测试均纳入本轮回归。
它们证明已覆盖的代码路径，不等于真实 Books 快捷键或已安装 Chrome 扩展的完整验收。
本轮没有重置权限，也没有新增真实 Books、已加载浏览器扩展或 Air 的实机验收记录。

## 0.2.0 云端候选验证

在明确许可及调用额度下，对 24 条合成英文分别调用原有 DeepSeek 辅助路径和新的主查词路径，
共 48 次，无自动重试。初次候选暴露了无语境查询缺主释义、备选混入无关解释的问题。
修正采用一般性的任务区分：无语境使用普通词典任务，上下文任务给出选词的简短释义，不生成备选列表。
没有加入按单词硬编码的译法，也没有修改本地模型默认值。

最终候选在单独获批的 24 次调用中验证同一组样例，使用生产 `DeepSeekProvider(.lookup)`，
模型 `deepseek-flash`、关闭 thinking、temperature 0、每次最多 1,024 输出 token。
24 次均完整返回，响应时间中位数 **1.04 秒**。逐条检查主释义、词性、句译和未知词处理：

| 范围 | 最终观察 |
| --- | --- |
| 收费/充电、银行/河岸、经营/流动、海豹/封好、罚款/正常、熊/忍受 | 主词义及词性符合相应原句 |
| making mistakes、look up | 识别犯错搭配和查阅短语；making 的第二种措辞仍略生硬 |
| There 存在句、地点 there、天气句 It | 区分语法角色，不统一套用地点或物体含义 |
| 三个未知标签场景 | 不编造主含义或词性，句译保留原拼写 |
| 无语境 charged | 给出常见形容词含义，句译为空；不冒称已确定具体语境 |
| 否定、数量及并列分句 | 句译保留所供句子的关键内容 |

这组固定验收要求通过。8 条新增对照在首次运行后已成为回归样例，最终复验不是盲测。
只测一轮，不能估计广泛准确率、长期稳定性或其他模型的质量。未改善本地 qwen2.5:7b 的上述失败项。
模型调用使用生产手动输入请求构造，**不代表真实 Books、Readest、Session Manager、Markdown
或已安装浏览器扩展均已通过上下文捕获验收**。捕获质量与解释质量仍分别判断。

本机原生测试版已实际走通首次配置、本地模式选择、合成 bank 原句查询及公开版本检查。
跨机安装、升级与逐应用兼容性的结果应随发行记录分别列出；没有实测的项目保持未验证。
