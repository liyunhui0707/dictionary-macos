# Dictionary 0.9.1 — local candidate

This **unpublished** candidate adds a Books OCR timing fix to the [0.9.0 candidate](0.9.0.md).
The owner approved local packaging and scoped installation/Books acceptance on two Macs.
The Chromium extension remains **0.2.1**. No public Release or website deployment is implied.

## Changes

- Books OCR receives the remaining capture-time budget instead of always stopping at three seconds.
  When time permits, the extended recognition window reserves three seconds for the final two
  ScreenCaptureKit waits. Quick recovery near the deadline remains possible; a late result is rejected.
- Source identity and cancellation are checked again before starting recognition. Native text remains
  the fallback, and screen-derived sentences still require stable pixels and explicit preview confirmation.
- Private QA metadata records the recognition budget and elapsed time in milliseconds, without text or images.

The eight-second capture validity check is not a hard wall-clock cancellation guarantee for the entire
native pipeline. The original slow Vision case has **not been reproduced or isolated**. This patch fixes
the premature inner cutoff; it does not establish reliable context capture for every Books request or App.
Model selection, interpretation quality, permissions and browser pairing behavior are unchanged.

## Validation before packaging

The code at `b1fe450` passed 36 focused capture/recognition tests, the full 442-test Swift run in 59 suites,
and 127 Node tests. Controlled cases cover recognition beyond three seconds within the remaining budget,
exhausted time, fast recognition near the deadline, source changes, cancellation and late replies.

Local fixed-Testing acceptance confirmed the repeated-page second `bank`, preview abandonment and
confirmation, then the finance-page `bank` with its own original and meaning. The two OCR attempts
received 4.762/4.861-second budgets and took 237/78 milliseconds to recognize; finance used native text.
The abandoned preview submitted no query, and the two confirmed local queries completed.
These were development-Testing checks, not acceptance of the final 0.9.1 archives.

Six in-memory synthetic recognitions across three fresh processes did not reproduce the slow case.
A fresh process does not prove cold system caches. Candidate package inspection and installation
acceptance must be recorded separately; the original 0.9.0 files are retained unchanged.

## Distribution and remaining scope

The candidate keeps the **ad-hoc signed, unnotarized**, **Apple Silicon / macOS 14 or later** channel
and manual updates. A local daily build preserves its existing certificate identity and is a distinct
binary from the public ad-hoc candidate. Existing settings and a verified previous-version rollback
must be preserved. No model, API key, private log or signing material is bundled.

Browser-download quarantine first opening is separate from local or SCP installation and has not
been tested for this candidate. Required macOS consent is performed normally by the owner;
permissions are never reset as an update step. The known model-quality limits in
[quality evidence](../quality.md) still apply.
