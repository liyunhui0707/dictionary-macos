# Dictionary 0.9.2

Local release candidate, not yet published. The owner approved version 0.9.2 and
local candidate preparation. The Chromium extension remains **0.2.1**. Existing
0.9.1 downloads and daily installations remain unchanged until separately scoped
installation and delivery steps complete.

## Changes

- Getting Started offers an actionable next step based on the selected reading
  route and the latest explicit service check or model response. A new response
  can supersede an older failed check; a newer failed check is not hidden by an
  earlier successful self-test.
- Local service unavailable, timeout, model/interface rejection and invalid
  protocol responses have distinct recovery messages and fixed diagnostic
  categories. Cancellation remains cancellation and does not trigger a retry.
- A model response without a usable meaning prompts input/model/service review,
  rather than suggesting that selection permissions must be reset.
- Changing reading routes clears the previous route's reading confirmation while
  retaining the main-window query record. Browser files being prepared still do
  not prove loading, pairing, shortcut registration or a successful lookup.
- Feedback needs only the application, selection and observed problem. Version,
  model and a previewed diagnostic report can be supplied later when useful.

No automatic queries, model downloads, service switches, permission changes or
feedback uploads were added. Capture integration and extension protocol are
unchanged. Updates remain manual.

## Interpretation quality

One frozen candidate was compared on two installed local models, using 16 fixed
and 16 independent synthetic cases per model, for 64 calls without retries.
Both promotions were rejected because critical meaning/POS or sentence-relation
errors remained. The research stays in opt-in tests; **production prompts,
generation settings and default model are unchanged**. See [quality evidence](../quality.md).
This version does not claim to resolve those semantic defects or support every App.

## Validation and delivery boundaries

The integrated implementation at `a856f74` passed 458 Swift tests in 62 suites and
127 QA/extension tests locally. PR #12 and its main-branch CI passed Swift, separate
DOM/Safari capture groups, integration/packaging tests and release compilation.
Controlled lifecycle and HTTP tests cover the changed setup/recovery paths;
native views were rendered in invisible windows. These are not new physical
shortcut, permission or installed-binary acceptance results.

After selecting version 0.9.2, the candidate working tree passed the same 458-test
Swift run in 62 suites and 127 QA/extension tests without live model calls.
Exact ZIP/DMG payload inspection and upgrade receipts will be recorded separately. Previous scoped 0.9.1 Books and earlier browser acceptance applies
only to unchanged paths and is not presented as a new 0.9.2 real-App test. New manual
checks are restricted to material changes or distribution risks, with no routine
two-Mac repetition of accepted bank queries or service restarts.

The intended channel remains **ad-hoc signed, unnotarized**, **Apple Silicon /
macOS 14 or later**, with manual replacement and a preserved rollback archive.
The local daily build must retain its existing certificate identity and is a
different binary from public ad-hoc assets. No model, credential, private evidence
or signing material may enter the public payload. Browser-quarantine first open
requires separate evidence; a matching local/SCP archive is not that evidence.
